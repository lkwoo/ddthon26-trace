## P1. 데브 (개발자 — Understand)
- **역할**: 낯선 코드베이스에 갓 투입된 개발자
- **핵심 질문**: "어디를 바꿔야 하지?"
- **맥락/빈도**: 변경 티켓을 받을 때마다(상시). 요구사항·OpenAPI·소스·DB·테스트를 각각 열어 수작업 대조
- **목표**: 빠른 시스템 이해, 영향받는 컴포넌트를 놓치지 않기
- **불편(Pain)**: 정보가 파일 단위로 흩어져 기능 단위로 재구성 안 됨; 문서-구현 드리프트를 모른 채 착수
- **성공 기준**: 구현 착수 전, 관련 코드/API/DB/설정/테스트/문서를 근거와 함께 파악
- **기술 수준**: 높음 (Claude Code 상시 사용)

## P2. 마이라 (유지보수자 — Maintain)
- **역할**: 운영 이슈·정책 불일치를 조사하는 유지보수자
- **핵심 질문**: "왜 이 문제가 생겼고, 또 무엇을 고쳐야 하지?"
- **맥락/빈도**: 장애/정책 불일치 조사 시
- **목표**: 근본 원인 후보를 빨리 좁히고, 함께 고쳐야 할 테스트·문서까지 포함해 재발 방지
- **불편(Pain)**: 문서/구현 드리프트를 탐지 못함; 불완전한 수정으로 재발
- **성공 기준**: 관련 충돌·낡은 지식 식별 + 영향 범위 확인 + Maintenance Plan
- **기술 수준**: 높음

## P3. 피엠 (기획자/PM — Plan Change)
- **역할**: 새 요구사항/정책 변경의 파급을 가늠하는 기획자
- **핵심 질문**: "이 요구사항이 바뀌면 영향은 어디까지 번지지?"
- **맥락/빈도**: 요구사항/정책 변경 평가 시
- **목표**: 코드를 직접 읽지 않고 현재 동작 이해 + 구현 복잡도·리스크 조기 파악
- **불편(Pain)**: 구현 복잡도가 늦게 드러남; 상충 정책을 뒤늦게 발견
- **성공 기준**: 구현 범위·리스크 요약·개발 전 결정 지점
- **기술 수준**: 중간 (자연어로 에이전트에 요청)

## A1. 클로드 코드 (AI 코딩 에이전트 — 1급 액터)
- **역할**: 위 세 사람을 대신해 실제로 코드를 생성하는 MCP 클라이언트
- **핵심 질문**: "구현 직전, 무엇이 관련되고 무엇이 어긋나 있는가?"
- **맥락/빈도**: 코드 생성 착수 직전 TRACE 도구 자동 호출
- **목표**: 낡거나 잘못된 명세 위에서 자신 있게 잘못 구현하는 것을 방지 — 근거를 갖고 착수
- **불편(Pain)**: 충돌을 모른 채 빠르게, 같은 오해 위에서 코드 생성
- **성공 기준**: 구조화된 도구 결과(Feature→Conflict→Impact→Evidence 순, 근거 포함)로 사람에게 "왜"를 설명 가능
- **기술 수준**: 도구 스키마 기반 자동 호출
