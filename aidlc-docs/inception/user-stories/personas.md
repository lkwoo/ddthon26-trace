> **작성일**: 2026-09-08

본 시스템은 **Dual-Interface** 모델이므로, 비인간 행위자인 **LLM 에이전트**를 1급 페르소나로 포함한다. (계획 Q1=A: 2 페르소나)

---

## P1 — LLM 에이전트 (Consuming Agent)

| 항목 | 내용 |
|---|---|
| **유형** | 비인간 (Non-human actor) |
| **정체** | Claude Desktop / Claude Code 등 MCP 클라이언트를 통해 지식 베이스를 소비하는 코딩/작업 에이전트 |
| **접점** | MCP 서버 (stdio 전송) — Resources, Tools, Prompts |
| **주요 목표** | 프로젝트 전체 맥락을 최소 토큰으로 정확히 파악하여 코드 작업(이해·수정·테스트 작성 등)을 수행 |
| **핵심 니즈** | ① 구조/요약/관계 데이터에 URI로 접근<br>② 키워드+그래프 기반 정확한 검색<br>③ 토큰 예산에 맞춘 최적 스니펫<br>④ MCP 출력과 상호작용해 작성한 **심화 요약/작업 결과를 Update Tool로 저장**<br>⑤ 온보딩/작업별 프롬프트 템플릿 |
| **제약/특성** | 컨텍스트 윈도우(토큰) 한계에 민감. 응답 지연이 반복 루프를 방해하면 안 됨(1초 이내 지향). 결정적·구조화된 응답 선호. |
| **성공 기준** | 필요한 맥락을 적은 토큰으로 빠르고 정확하게 획득; 잘못된/과다한 컨텍스트로 인한 오작동 최소화 |
| **관련 요구사항** | FR-A1~A6, FR-E1~E5, NFR-P1, NFR-P2 |
| **아키텍처 참고** | 엔진(MCP 서버)은 LLM을 호출하지 않는다. **모든 LLM 추론/요약은 이 에이전트가 담당**하며, 엔진의 구조화된 출력과 상호작용한다. (2026-09-08 정정) |

## P2 — 개발자 / 운영자 (Human Developer / Operator)

| 항목 | 내용 |
|---|---|
| **유형** | 인간 (단일 개발자) |
| **정체** | 프로젝트를 소유한 단일 개발자. 지식 베이스의 **인제스천·검토·재동기화**를 모두 수행하며, 위키 콘텐츠 품질 검토(리뷰어 역할)도 겸함 |
| **접점** | CLI/실행 명령(인제스천·재동기화), 경량 웹 뷰어(트리·위키·의존성 그래프·검토) |
| **주요 목표** | 로컬 프로젝트를 지식 베이스로 변환하고, 결과를 눈으로 검토하며, 소스 변경 시 최신 상태로 유지 |
| **핵심 니즈** | ① 소스 코드+Markdown 인제스천 실행<br>② 트리/위키/의존성 그래프로 시각적 검토<br>③ 엔진이 생성/수정한 지식 검토<br>④ 소스 변경 시 재동기화<br>⑤ Git 친화적 산출물로 버전 관리 |
| **제약/특성** | 로컬 파일 시스템 + Git 환경. 최소 의존성의 경량 도구 선호. "엔진 우선" 정책상 수동 편집은 재동기화 시 덮어써질 수 있음을 인지. LLM API 호출 비용/지연에 민감. |
| **성공 기준** | 적은 설정으로 정확한 위키 생성·검토; 소스와 위키의 일관성을 재동기화로 신뢰성 있게 유지; diff 가능한 텍스트 산출물 |
| **관련 요구사항** | FR-H1~H5, FR-E1~E5, FR-C1, NFR-C2, NFR-C3, NFR-D1, NFR-E1, NFR-R2, NFR-T1~T3 |
