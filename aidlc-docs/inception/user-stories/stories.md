# 🅐 Epic A — Agent Interface (MCP Server)

에이전트(P1)가 stdio MCP를 통해 지식 베이스를 소비하는 인터페이스.

## US-A1 — MCP Resources 노출 (구조·요약·관계)
**[P1]** · 추적성: FR-A1 (A1.1, A1.2, A1.3)

> **As a** LLM 에이전트,
> **I want** 프로젝트 구조·파일/모듈 요약·관계 그래프 데이터를 URI 형태의 MCP Resource로 조회하고 싶다,
> **so that** 파일 원문을 모두 읽지 않고도 프로젝트 맥락을 구조화된 형태로 파악할 수 있다.

**인수 기준**
- **AC-1 (Structure Resource, FR-A1.1)**: *Given* 인제스천이 완료된 프로젝트가 있을 때, *When* 에이전트가 구조 Resource URI를 요청하면, *Then* 프로젝트의 논리적 계층 구조(디렉토리/모듈 트리)가 구조화된 형태로 반환된다.
- **AC-2 (Summary Resource, FR-A1.2)**: *Given* 요약이 생성된 파일/모듈이 있을 때, *When* 에이전트가 해당 Summary Resource URI를 요청하면, *Then* 그 파일/모듈의 핵심 요약이 반환된다.
- **AC-3 (Relationship Resource, FR-A1.3)**: *Given* 관계 그래프가 구성되어 있을 때, *When* 에이전트가 Relationship Resource URI를 요청하면, *Then* 모듈 간 의존성/호출 관계 데이터가 반환된다.
- **AC-4 (미존재)**: *Given* 인제스천되지 않았거나 존재하지 않는 대상의 URI일 때, *When* 요청하면, *Then* 명확한 "리소스 없음" 응답이 반환되고 서버는 중단되지 않는다.

## US-A2 — Semantic Query Tool (키워드 + 그래프 검색)
**[P1]** · 추적성: FR-A2, NFR-P1

> **As a** LLM 에이전트,
> **I want** 키워드 및 코드 구조(그래프) 기반으로 지식 베이스를 검색하고 싶다,
> **so that** 작업과 관련된 파일·심볼·관계를 빠르게 찾아낼 수 있다.

**인수 기준**
- **AC-1 (키워드 검색)**: *Given* 인제스천된 지식 베이스에서, *When* 에이전트가 키워드 질의를 보내면, *Then* 관련 파일/심볼 결과가 관련도 순으로 반환된다.
- **AC-2 (그래프 검색)**: *Given* 특정 심볼(함수/클래스)이 주어졌을 때, *When* 에이전트가 "이 심볼을 호출/참조하는 대상"을 질의하면, *Then* 관계 그래프에 기반한 연결 심볼 목록이 반환된다.
- **AC-3 (결과 없음)**: *Given* 매칭이 없는 질의일 때, *When* 검색하면, *Then* 빈 결과 집합이 오류 없이 반환된다.
- **AC-4 (성능, NFR-P1)**: *Given* MVP 규모의 프로젝트에서, *When* 조회 질의를 보내면, *Then* 응답이 1초 이내를 목표로 반환된다.

## US-A3 — Smart Snippet Tool (토큰 최적화 스니펫)
**[P1]** · 추적성: FR-A3, NFR-P2

> **As a** LLM 에이전트,
> **I want** 요청 컨텍스트의 토큰 예산에 맞춰 최적 범위로 잘린 코드 스니펫을 받고 싶다,
> **so that** 컨텍스트 윈도우를 낭비하지 않으면서 필요한 코드만 확보할 수 있다.

**인수 기준**
- **AC-1 (범위 선택)**: *Given* 대상 심볼/파일과 토큰 예산이 주어졌을 때, *When* 스니펫을 요청하면, *Then* 예산을 초과하지 않는 범위에서 의미적으로 완결된 스니펫(예: 함수 단위)이 반환된다.
- **AC-2 (토큰 효율, NFR-P2)**: *Given* 반환 스니펫이 있을 때, *Then* 응답에 사용/추정 토큰 정보 또는 절단(truncation) 표시가 포함되어 에이전트가 예산을 관리할 수 있다.
- **AC-3 (예산 초과)**: *Given* 요청 범위가 예산보다 클 때, *When* 스니펫을 요청하면, *Then* 우선순위(요청 대상 근접) 기준으로 축약된 스니펫과 함께 축약되었음이 표시된다.

## US-A4 — Update Tool (에이전트 심화 요약·작업 결과 반영)
**[P1]** · 추적성: FR-A4, FR-E3, FR-C1

> **As a** LLM 에이전트,
> **I want** 내가 MCP 출력과 상호작용해 작성한 심화 요약/노트/작업 결과를 지식 베이스에 반영하고 싶다,
> **so that** 엔진의 결정적 구조 추출을 보완하는 자연어 지식을 축적하고 이후 조회 시 재사용할 수 있다.

> 아키텍처 참고: 엔진은 LLM을 호출하지 않는다. **자연어 심화 요약은 에이전트가 작성**하며, 그 저장 통로가 이 Update Tool이다. (병행 모델: 엔진 구조 추출(US-E3) + 에이전트 심화 요약)

**인수 기준**
- **AC-1 (심화 요약 반영, FR-E3)**: *Given* 에이전트가 작성한 유효한 요약/노트 페이로드가 주어졌을 때, *When* Update Tool을 호출하면, *Then* 해당 항목이 지식 베이스(위키)에 저장/갱신되고 성공 결과가 반환된다.
- **AC-2 (엔진 우선 정책, FR-C1)**: *Given* 소스 코드로부터 자동 생성되는 구조 항목에 대해, *Then* 재동기화 시 소스 기준으로 재생성되며, 에이전트가 작성한 심화 요약의 보존/재생성 정책(엔진 우선)이 명확히 문서화/노출된다.
- **AC-3 (유효성)**: *Given* 잘못된/불완전한 페이로드일 때, *When* 호출하면, *Then* 명확한 검증 오류가 반환되고 지식 베이스는 변경되지 않는다.

## US-A5 — MCP Prompts (온보딩 · 작업별 프롬프트 템플릿)
**[P1]** · 추적성: FR-A5 (A5.1, A5.2)

> **As a** LLM 에이전트,
> **I want** 특정 상황에 최적화된 프롬프트 템플릿을 MCP Prompt로 제공받고 싶다,
> **so that** 프로젝트 맥락 학습이나 특정 작업을 효율적으로 시작할 수 있다.

**인수 기준**
- **AC-1 (Onboarding Prompt, FR-A5.1)**: *Given* 신규 에이전트 세션에서, *When* 온보딩 프롬프트를 요청하면, *Then* 프로젝트 전체 맥락을 빠르게 학습하도록 구성된 프롬프트 템플릿이 반환된다.
- **AC-2 (Task-Specific Prompt, FR-A5.2)**: *Given* 특정 작업(예: 단위 테스트 작성)이 지정되었을 때, *When* 해당 작업 프롬프트를 요청하면, *Then* 그 작업에 필요한 지식/지침에 집중한 프롬프트 템플릿이 반환된다.

## US-A6 — MCP 서버 stdio 연결
**[P1] [P2]** · 추적성: FR-A6, NFR-E1

> **As a** 개발자(P2)가 설정하고 LLM 에이전트(P1)가 사용하는 주체로서,
> **I want** MCP 서버가 stdio 전송으로 로컬 클라이언트에서 직접 실행되기를 원한다,
> **so that** 별도 네트워크 서버 없이 Claude Desktop/Claude Code 등에서 즉시 지식 베이스에 연결할 수 있다.

**인수 기준**
- **AC-1 (연결)**: *Given* 로컬 MCP 클라이언트 설정에 서버가 등록되었을 때, *When* 클라이언트가 서버를 기동하면, *Then* stdio 전송으로 핸드셰이크가 성립하고 Resources/Tools/Prompts 목록이 노출된다.
- **AC-2 (로컬 환경, NFR-E1)**: *Given* 단일 개발자 로컬 파일 시스템 환경에서, *Then* 서버는 외부 서비스 의존 없이(파서/LLM 호출 제외) 기동·동작한다.

# 🅗 Epic H — Human Interface (Web Viewer)

개발자(P2)가 경량 웹 뷰어로 지식 베이스를 시각적으로 검토하는 인터페이스.

## US-H1 — Interactive Tree View
**[P2]** · 추적성: FR-H1

> **As a** 개발자,
> **I want** 프로젝트의 디렉토리 및 논리적 의존성 구조를 트리 형태로 보고 싶다,
> **so that** 프로젝트 전체 구성을 한눈에 파악하고 탐색할 수 있다.

**인수 기준**
- **AC-1 (트리 표시)**: *Given* 인제스천된 프로젝트에서, *When* 웹 뷰어를 열면, *Then* 디렉토리/모듈 계층이 트리로 렌더링된다.
- **AC-2 (탐색)**: *Given* 트리가 표시된 상태에서, *When* 노드를 펼치거나 선택하면, *Then* 하위 항목이 표시되고 선택 항목의 콘텐츠 뷰로 연결된다.

## US-H2 — Wiki Content Viewer
**[P2]** · 추적성: FR-H2, FR-H5

> **As a** 개발자,
> **I want** Markdown으로 정리된 명세·코드 설명을 웹에서 렌더링해 읽고 싶다,
> **so that** 정리된 지식을 편하게 열람할 수 있다.

**인수 기준**
- **AC-1 (렌더링)**: *Given* 특정 파일/모듈의 위키 Markdown이 있을 때, *When* 해당 항목을 열면, *Then* Markdown이 HTML로 렌더링되어 표시된다.
- **AC-2 (경량 SSR, FR-H5)**: *Given* 웹 뷰어 페이지 요청 시, *Then* 서버사이드 렌더링(정적 Markdown 렌더 위주)으로 최소 의존성으로 응답한다.

## US-H3 — Dependency Visualization
**[P2]** · 추적성: FR-H3

> **As a** 개발자,
> **I want** 코드 간 호출/의존성 관계를 그래프 형태로 시각화해서 보고 싶다,
> **so that** 모듈 간 결합과 영향 범위를 직관적으로 이해할 수 있다.

**인수 기준**
- **AC-1 (그래프 표시)**: *Given* 관계 그래프 데이터가 있을 때, *When* 의존성 시각화를 열면, *Then* 노드(파일/함수/클래스)와 엣지(호출/의존)가 그래프로 표시된다.
- **AC-2 (연계)**: *Given* 그래프가 표시된 상태에서, *When* 노드를 선택하면, *Then* 해당 항목의 위키 콘텐츠/요약으로 이동할 수 있다.

## US-H4 — Content Review (엔진 산출 지식 검토)
**[P2]** · 추적성: FR-H4, FR-C1

> **As a** 개발자(리뷰어 겸임),
> **I want** 엔진이 생성/수정한 지식 베이스 내용을 웹에서 검토하고 싶다,
> **so that** 요약/구조/관계의 정확성을 확인하고 신뢰할 수 있다.

**인수 기준**
- **AC-1 (검토 열람)**: *Given* 엔진이 생성/갱신한 항목이 있을 때, *When* 개발자가 뷰어에서 해당 항목을 열면, *Then* 생성된 요약·구조·관계 내용을 확인할 수 있다.
- **AC-2 (엔진 우선 고지, FR-C1)**: *Given* 콘텐츠가 소스 코드로부터 자동 생성되었을 때, *Then* 해당 내용이 재동기화 시 소스 기준으로 재생성됨(수동 수정은 유지되지 않을 수 있음)이 사용자에게 인지되도록 표시/문서화된다.

# 🅔 Epic E — Knowledge Engine (Core)

개발자(P2)가 실행하고, 그 산출물을 에이전트(P1)가 소비하는 핵심 엔진.

> **아키텍처 원칙 (2026-09-08 정정)**: 엔진은 LLM/외부 API를 **호출하지 않으며** 결정적/로컬로 동작한다. 엔진은 결정적 구조 추출(US-E3)을 제공하고, **자연어 심화 요약은 소비 에이전트가 작성해 Update Tool(US-A4)로 저장**한다.

## US-E1 — Multi-format Ingestion (소스 코드 + Markdown)
**[P2]** · 추적성: FR-E1

> **As a** 개발자,
> **I want** 소스 코드와 Markdown 파일을 수집·분석·구조화하도록 인제스천을 실행하고 싶다,
> **so that** 로컬 프로젝트를 지식 베이스로 변환할 수 있다.

**인수 기준**
- **AC-1 (수집)**: *Given* 소스 코드/Markdown이 포함된 로컬 프로젝트 경로에서, *When* 인제스천을 실행하면, *Then* 대상 파일들이 수집되어 분석 대상으로 등록된다.
- **AC-2 (MVP 범위)**: *Given* PDF/HTML/PPT 등 MVP 제외 포맷 파일이 섞여 있을 때, *When* 인제스천하면, *Then* 지원 포맷(코드/Markdown)만 처리되고 미지원 포맷은 오류 없이 건너뛰며 그 사실이 기록된다.

## US-E2 — Graph Construction (tree-sitter, 다국어 확장)
**[P2]** · 추적성: FR-E2, NFR-C2

> **As a** 개발자,
> **I want** 파서 기반으로 파일/함수/클래스 간 호출·의존 관계 그래프가 구성되기를 원한다,
> **so that** 코드 구조 기반 검색과 의존성 시각화의 토대를 확보할 수 있다.

**인수 기준**
- **AC-1 (그래프 생성)**: *Given* 지원 언어의 소스 코드가 인제스천되었을 때, *When* 그래프 구성을 실행하면, *Then* 심볼(파일/함수/클래스) 노드와 호출/의존 엣지가 생성된다.
- **AC-2 (확장성, NFR-C2)**: *Given* 새 언어 파서를 플러그인 형태로 추가할 때, *Then* 기존 엔진 코드 변경 없이 해당 언어가 그래프 구성 대상에 포함될 수 있는 구조다.
- **AC-3 (파싱 실패)**: *Given* 파싱 불가/부분 실패 파일이 있을 때, *When* 그래프를 구성하면, *Then* 해당 파일은 건너뛰거나 부분 처리되고 전체 구성은 중단되지 않으며 실패가 기록된다.

## US-E3 — 결정적 구조 추출 요약 (Structured Extraction, LLM 미호출)
**[P2]** · 추적성: FR-E3, NFR-C3

> **As a** 개발자,
> **I want** 엔진이 LLM 호출 없이 결정적 방식으로 코드/문서의 구조적 요약(시그니처·docstring·주석·헤딩 등)을 추출하기를 원한다,
> **so that** 외부 API 비용/비결정성 없이 에이전트가 소비할 기본 요약 정보를 확보할 수 있다.

**인수 기준**
- **AC-1 (구조 추출)**: *Given* 인제스천된 소스/Markdown 파일에 대해, *When* 구조 추출을 실행하면, *Then* 함수/클래스 시그니처, docstring, 주석, Markdown 헤딩 등에서 파일/모듈의 구조적 요약이 생성되어 Summary Resource/위키로 저장된다.
- **AC-2 (LLM 미호출, NFR-C3)**: *Given* 구조 추출 과정에서, *Then* 엔진은 LLM/외부 API를 전혀 호출하지 않고 로컬에서만 처리한다.
- **AC-3 (결정성)**: *Given* 동일한 입력 파일을 재처리할 때, *Then* 동일한 구조 요약 결과가 결정적으로 생성된다.

> 참고: 자연어 **심화 요약**은 엔진이 아니라 소비 에이전트가 작성하여 Update Tool로 저장한다 → **US-A4** 참조. (병행 모델 Q1=D)

## US-E4 — Persistence (Markdown + JSON, Git 친화)
**[P2]** · 추적성: FR-E4, NFR-D1

> **As a** 개발자,
> **I want** 생성된 지식(요약·구조·관계 그래프)이 파일 기반(Markdown + JSON)으로 저장되기를 원한다,
> **so that** Git으로 버전 관리하고 변경을 diff로 검토할 수 있다.

**인수 기준**
- **AC-1 (저장)**: *Given* 요약/구조/그래프가 생성되었을 때, *When* 저장을 수행하면, *Then* Markdown(문서형)과 JSON(구조/그래프형)으로 파일 시스템에 기록된다.
- **AC-2 (Git 친화, NFR-D1)**: *Given* 동일 소스를 재인제스천했을 때(내용 무변경), *Then* 산출 파일은 결정적(deterministic)으로 생성되어 불필요한 diff 노이즈가 최소화된다.

## US-E5 — Re-sync (재동기화, 엔진 우선)
**[P2]** · 추적성: FR-E5, FR-C1

> **As a** 개발자,
> **I want** 소스 코드 변경 시 명시적 재동기화로 위키를 소스 기준으로 재생성하고 싶다,
> **so that** 소스와 지식 베이스의 일관성을 신뢰성 있게 유지할 수 있다.

**인수 기준**
- **AC-1 (재생성)**: *Given* 소스 코드가 변경된 상태에서, *When* 재동기화를 실행하면, *Then* 변경된 부분의 구조/요약/관계가 소스 기준으로 재생성된다.
- **AC-2 (엔진 우선, FR-C1)**: *Given* 사람이 수동 수정한 자동 생성 항목이 있을 때, *When* 재동기화하면, *Then* 소스 기준으로 덮어써질 수 있으며 이 동작이 정책대로 수행된다.
- **AC-3 (명시적 실행)**: *Given* 소스가 변경되었으나 재동기화를 실행하지 않은 상태에서, *Then* 위키는 자동으로 변경되지 않는다(실시간 자동 동기화는 MVP 범위 밖).

# 🅝 Epic N — 교차 관심사 / NFR 스토리 (Cross-Cutting)

(계획 Q6=C) 개별 기능 스토리의 인수 기준에 반영된 NFR 외에, 시스템 전반에 걸친 품질 속성을 별도 스토리로 관리한다.

## US-N1 — 응답 지연 최소화 (Low Latency)
**[P1]** · 추적성: NFR-P1

> **As a** LLM 에이전트,
> **I want** 핵심 조회(Resource/Tool)의 응답이 빠르기를 원한다,
> **so that** 반복 작업 루프가 지연으로 방해받지 않는다.

**인수 기준**
- **AC-1**: *Given* MVP 규모 프로젝트에서, *When* 핵심 조회(Resource 읽기, Query, Snippet)를 호출하면, *Then* 응답 시간 1초 이내를 목표로 한다.
- **AC-2**: *Given* 조회 성능을 측정할 때, *Then* 응답 시간을 계측할 수 있는 수단(로깅/지표)이 존재한다.

## US-N2 — 토큰 효율 (Token Efficiency)
**[P1]** · 추적성: NFR-P2

> **As a** LLM 에이전트,
> **I want** 제공되는 Resource/Tool 결과가 Smart Chunking·Summarization으로 토큰 효율적이기를 원한다,
> **so that** 컨텍스트 윈도우 낭비 없이 필요한 정보를 얻는다.

**인수 기준**
- **AC-1**: *Given* 에이전트에 반환되는 모든 결과에 대해, *Then* 원문 전체 대신 요약/청크 형태로 토큰을 최소화하여 제공된다.
- **AC-2**: *Given* 결과가 크기 제한을 초과할 때, *Then* 축약/청킹이 적용되고 절단 사실이 표시된다.

## US-N3 — 엔진 로컬성/결정성 (Local & Deterministic Engine)
**[P2]** · 추적성: NFR-C3, NFR-R1

> **As a** 개발자,
> **I want** 엔진이 파싱·그래프·구조 추출·저장 전 과정에서 외부 API(LLM 포함)를 호출하지 않고 결정적으로 동작하기를 원한다,
> **so that** 외부 API 비용/지연·비결정성 없이 재현 가능하게 지식 베이스를 생성할 수 있다.

> 변경 이력: 기존 "LLM 제공자 추상화(NFR-C1)" 스토리는 아키텍처 정정(엔진 LLM 미호출)으로 **폐지**되고 본 스토리로 대체됨. (2026-09-08)

**인수 기준**
- **AC-1 (외부 호출 없음)**: *Given* 인제스천~저장 전 과정에서, *Then* 엔진은 LLM/외부 API를 호출하지 않는다(모든 LLM 상호작용은 에이전트 측에서 발생).
- **AC-2 (결정성)**: *Given* 동일 입력을 재처리할 때, *Then* 산출물이 결정적으로 동일하게 생성된다.

## US-N4 — 파서 확장성 (Parser Extensibility)
**[P2]** · 추적성: NFR-C2

> **As a** 개발자,
> **I want** 코드 그래프 분석이 언어별 파서를 플러그인으로 추가할 수 있는 구조이기를 원한다,
> **so that** 다국어 프로젝트로 점진 확장할 수 있다.

**인수 기준**
- **AC-1**: *Given* 신규 언어 파서 플러그인을 추가할 때, *Then* 기존 코어 로직 수정 없이 해당 언어가 그래프 구성 대상에 편입된다.
- **AC-2**: *Given* 특정 언어 파서가 없을 때, *Then* 해당 언어 파일은 미지원으로 건너뛰고 전체 처리는 계속된다.

## US-N5 — Git 친화 로컬 저장 (Git-Friendly Local Storage)
**[P2]** · 추적성: NFR-D1, NFR-E1

> **As a** 개발자,
> **I want** 지식 산출물이 텍스트 기반으로 로컬 파일 시스템에 저장되기를 원한다,
> **so that** Git으로 버전 관리·diff·리뷰가 가능하다.

**인수 기준**
- **AC-1**: *Given* 산출물이 저장될 때, *Then* 모두 텍스트(Markdown/JSON) 형식이며 바이너리 의존이 없다.
- **AC-2**: *Given* 동일 입력을 재처리할 때, *Then* 산출물이 결정적으로 생성되어 diff 노이즈가 최소화된다.

## US-N6 — 속성 기반 테스트 품질 (Property-Based Testing, Partial)
**[P2]** · 추적성: NFR-T1, NFR-T2, NFR-T3

> **As a** 개발자,
> **I want** 순수 함수 및 직렬화 왕복(round-trip) 로직에 속성 기반 테스트(PBT)를 적용하고 싶다,
> **so that** 파싱/직렬화/구조 변환의 정확성을 광범위한 입력에 대해 검증할 수 있다.

**인수 기준**
- **AC-1 (Round-trip, PBT-02)**: *Given* 지식 산출물의 직렬화/역직렬화(예: JSON ↔ 그래프 모델) 로직에 대해, *Then* 임의 입력에 대해 `deserialize(serialize(x)) == x` 속성이 검증된다.
- **AC-2 (Invariant, PBT-03)**: *Given* 순수 변환 함수(예: 청킹/구조 정규화)에 대해, *Then* 불변식(길이/구조 보존 등)이 임의 입력에 대해 검증된다.
- **AC-3 (프레임워크/재현성, PBT-07/08/09)**: *Given* PBT를 실행할 때, *Then* 선정된 Python PBT 프레임워크(예: Hypothesis)로 실행되며, 생성기 품질이 확보되고, 실패 시 shrinking 및 재현 가능한 시드가 제공된다.
- 참고: 위 PBT-02/03/07/08/09는 차단(blocking) 제약이며, 그 외 PBT 규칙은 권고(advisory) 사항이다.

## US-N7 — 자원 인지 (Resource Awareness)
**[P2]** · 추적성: NFR-R2

> **As a** 개발자,
> **I want** 파싱·그래프 생성의 컴퓨팅 자원 사용을 파악하고 관리하고 싶다,
> **so that** 대규모 프로젝트에서도 예측 가능한 시간/자원으로 운용할 수 있다.

> 참고: 엔진은 외부 API(LLM)를 호출하지 않으므로 엔진 자체의 API 비용은 없다(NFR-R1). LLM 사용 비용은 에이전트 측 관심사로 본 스토리 범위 밖.

**인수 기준**
- **AC-1 (재처리 최소화)**: *Given* 변경되지 않은 대상에 대해, *When* 인제스천/추출을 재실행하면, *Then* 캐시/스킵으로 불필요한 재처리를 피한다.
- **AC-2 (자원 인지, NFR-R2)**: *Given* 인제스천/그래프 생성을 실행할 때, *Then* 처리 대상 규모(파일 수/심볼 수)와 소요를 확인할 수 있는 정보가 제공된다.

# ✅ INVEST 준수 확인

- **Independent**: Epic/스토리 간 의존은 추적성으로 표기하되, 각 스토리는 독립적으로 검증 가능하도록 인수 기준을 구성.
- **Negotiable**: 구현 기술 세부는 후속 단계(Application/Infra/Code)에서 협상 가능하도록 "무엇/왜" 중심으로 기술.
- **Valuable**: 각 스토리는 P1(에이전트) 또는 P2(개발자)에게 명확한 가치를 제공.
- **Estimable**: 중간 세분화(FR당 1~2개)로 규모 추정이 가능.
- **Small**: 서브시스템/기능 단위로 분할되어 단일 반복에서 다룰 수 있는 크기.
- **Testable**: 모든 스토리가 Given/When/Then 인수 기준을 보유(측정/검증 가능).
