# Agentic Knowledge Base (MCP-based) 제약사항 및 제외 기능

## 1. 제외 기능 (Out of Scope)

### 1.1 고급 자동화 및 트리거
- **실시간 파일 시스템 감시**: 파일이 저장될 때마다 자동으로 업데이트를 수행하는 실시간 동기화 기능 (MVP 이후 단계로 고려).
- **복잡한 워크플로우 연동**: CI/CD 파이프라인과의 긴밀한 통합 및 자동 배포 연동.

### 1.2 고난도 콘텐츠 처리
- **심화 OCR (Optical Character Recognition)**: 이미지 내의 복잡한 레이아웃 및 손글씨 텍스트의 완벽한 구조화.
- **고급 문서 변환**: PDF 내의 복잡한 차트 및 다이어그램의 논리적 구조 완전 복원. (단, PDF의 텍스트 및 표(Table) 추출은 지원 범위에 포함됨.)
- **지원 외 문서 포맷**: 지원 문서 종류(Markdown, PDF, xlsx, csv) 이외의 포맷(예: PPT, HWP, 이미지 등)의 분석 및 구조화.

### 1.3 대규모 데이터 인덱싱 최적화
- **초대규모 코드베이스 처리**: 테라바이트(TB) 단위의 대규모 프로젝트에 대한 실시간 인덱싱 및 즉각적인 검색 성능 보장.

### 1.4 외부 서비스 연동
- **실시간 커뮤니케이션 도구 연동**: Slack, Teams 등 메신저와의 양방향 실시간 알림 연동.

## 2. 기술적 제약 및 성능 지표

### 2.1 성능 요구사항 (Agent Experience)
- **Low Latency**: MCP Tool의 응답 시간은 에이전트의 반복적인 루프를 방해하지 않도록 최적화되어야 함 (Target: 핵심 조회 기능 1s 이내).
- **Token Efficiency**: 에이전트에게 제공되는 모든 Resource 및 Tool 결과물은 불필요한 토큰 낭비를 최소화하도록 Smart Chunking 및 Summarization이 적용되어야 함.

### 2.2 데이터 일관성
- 위키의 구조는 소스 코드의 파일 경로 및 관계를 기반으로 생성되므로, 소스 코드의 대규모 리팩토링(파일 이동 등) 시 위키의 논리적 구조가 불일치할 수 있으며, 이는 재동기화(Re-indexing)를 통해 해소가 필요함.
- **문서 버전 관리**: 버전 관리는 분절화된 문서 청크(Chunk) 단위로 수행함. 문서가 추가될 때 청크 단위로 기존 청크(OLD ver)와 내용을 비교하여 신규 버전(NEW ver)으로 업데이트하므로, 청크 대응 관계 판별(내용 비교) 정확도에 따라 갱신 결과가 달라질 수 있음.

### 2.3 코드-문서(청크) 관계 저장 방식
- 문서는 의미 단위로 **분절화(Chunking)** 되어 저장되며, 관계 연결·검색의 최소 단위는 청크(Chunk)임. 청킹 전략(분절 크기·경계 기준)에 따라 관계 및 검색 품질이 달라질 수 있음.
- 함수/클래스와 분절화된 문서 청크의 관계는 다음 세 가지 방식을 조합하여 저장함:
    - **임베딩/벡터 유사도**: 임베딩 모델 및 유사도 임계값(Threshold) 설정에 따라 연결 결과 품질이 달라짐. 임베딩 생성 시 LLM/임베딩 API 비용이 발생할 수 있음.
    - **Markdown 링크 파싱**: 문서 청크에 명시적 링크가 존재해야 관계가 형성됨.
    - **태그 기반 연결**: 코드/문서 청크에 태그가 부여되어 있어야 관계가 형성됨.

### 2.3 비용 및 자원
- **LLM API 의존성**: 컨텍스트 분석 및 지능형 조회를 위해 LLM API를 사용할 경우, API 호출 비용과 네트워크 지연(Latency)이 발생함.
- **컴퓨팅 자원**: 프로젝트 규모가 커질수록 위키 트리 생성(Graph construction) 및 파싱에 필요한 컴퓨팅 자원이 증가함.

### 2.4 배포 및 설치
- **설치 간편성 우선**: 시스템 배포 시 사용자가 최대한 간편하게 설치할 수 있도록 설계함. 복잡한 수동 설정을 지양하고 단일 명령어 수준의 설치/실행(패키지 설치, 컨테이너 실행, 원클릭 스크립트 등)을 지향함.
- **사전 요구사항 최소화**: 설치에 필요한 Prerequisite를 최소화하며, 필요한 항목은 명확히 문서화함.

### 2.5 Agent 인지성 (Agent Discoverability)
- 본 시스템이 설치된 프로젝트에서, Agent는 이 시스템이 어떤 동작(제공 기능·도구·리소스)을 수행하는지 인지할 수 있어야 함.
- Agent가 필요한 시점에 시스템을 스스로 판단하여 사용할 수 있도록, MCP Tools/Resources에 명확한 설명(Description)과 사용 지침(용도·입력·출력·사용 시점)을 제공해야 함.
- 시스템의 존재와 활용 방법이 Agent 컨텍스트에서 자동으로 노출·발견 가능해야 하며, 별도의 수동 안내 없이도 적절한 상황에서 호출될 수 있어야 함.

### 2.6 환경 가정
- 본 프로젝트는 파일 시스템 기반의 로컬 또는 네트워크 드라이브 환경에서 동작하며, Git과 같은 버전 관리 시스템이 사용되는 환경을 상정함.
