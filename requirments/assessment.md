# 평가기준

1. **AI-DLC 사용 충실성 — 25점**

   * 문서를 얼마나 많이 냈는가가 아니라, AI와의 작업이 실제로 결과물을 만들어냈다는 증거를 봅니다.
   * 단계별 산출물이 서로 이어지는지, 앞 단계의 결정이 뒤에 반영됐는지가 기준입니다.
   * 어떤 도구를 썼는지는 점수와 무관합니다.

2. **문제 정의 및 해결 — 20점**

   * “누구의 어떤 문제를 어떻게 푸는가”가 읽는 사람에게 그대로 전달되는지를 봅니다.
   * 언제, 얼마나 자주 불편한지와 대상 사용자가 누구인지가 구체적일수록 높습니다.
   * 아이디어의 크기나 시장성은 여기서 보지 않습니다.

3. **창의성 — 15점**

   * 기존 도구와의 구조적 차별점이 코드나 설계 문서로 확인되는지를 봅니다.
   * “새롭다”는 주장만으로는 점수가 없습니다.
   * 반대로 흔한 분야라도 구조가 실제로 다르면 인정합니다.

4. **완성도 — 15점**

   * 만들려던 것이 코드로 실제로 동작하는지를 봅니다.
   * 동작하는 화면을 담은 시연 스크린샷을 screenshots/ 또는 result/ 에 꼭 넣어주세요.
   * 빌드·실행 가능성 — 의존성 선언, 진입점, 락파일, CI 설정
   * 에러 핸들링 — 주요 경로의 예외 처리와 전역 핸들러
   * 의도한 흐름의 코드상 완결성 — 진입점부터 호출이 실제 구현까지 닿는지
   * 실행 증거와 기능의 정합 — 스크린샷 속 화면이 README 의 기능과 맞는지
   * 미완성·스텁 코드 — TODO 나 빈 함수가 핵심 경로에 남아 있는지

5. **사용성 — 15점**

   * 처음 보는 사람이 시작까지 막히지 않고 가는지, 그리고 화면 앞에 앉았을 때, 다음에 무엇을 해야 할지 알 수 있는지를 봅니다.
   * 문서가 있는가가 아니라, 그대로 따라가서 막히지 않는가가 기준입니다.
   * 결과물이 웹 서비스라면 화면 자체가 사용법을 설명해야 하고, 라이브러리라면 API와 예제가 그 역할을 합니다. 형태에 맞춰 봅니다.
   * 시작하기까지의 경로 — 설치·실행·필요한 키와 계정
   * 사용 매뉴얼 — 실행한 뒤 무엇을 어떻게 하는지, 예제와 트러블슈팅
   * UI 직관성 — 화면을 보면 다음 행동을 알 수 있는지
   * 인터랙션 피드백 — 누른 뒤에 무슨 일이 일어났는지 알려주는지 (로딩·성공·오류 표시, 데이터가 없을 때의 빈 화면)
   * 사용자 흐름의 완결성 — 핵심 시나리오 하나를 끝까지 통과할 수 있는지

6. **유지보수성 및 보안 — 10점**
   * 후속 개발자가 이어받았을 때 곤란해지는 지점이 있는지를 봅니다.
   * 해커톤 산출물임을 감안해 프로덕션 수준을 요구하지는 않습니다.
   * 코드 구조·모듈화 · 설정 분리
   * 시크릿 관리 — 키가 코드에 박혀 있지 않은지
   * 인증·인가 및 입력 검증
   * 로깅·관측 가능성
